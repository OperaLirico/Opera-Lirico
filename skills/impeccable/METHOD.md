# impeccable 方法卡

上游 4.10.0 主文件 12.8KB，下面是能用上的部分。

## 一、先定 surface，再谈好坏

它是唯一一个把「这是什么页面」放在评审前面的技能。四种 surface：

| surface | 访客成功的样子 | 典型页面 | 野心怎么体现 |
|---|---|---|---|
| Persuade | 决定并行动 | 落地页、定价、活动页 | 大胆、有主张 |
| Operate | 完成一件任务 | 面板、仪表盘、编辑器、设置 | 精确与克制，熟悉模式优先 |
| Read | 看懂一件事 | 文档、文章、指南 | 结构服从理解 |
| Experience | 人在作品里 | 画廊、作品集 | 作品先说话，界面后退 |

对本站的判定：首页是 **Operate**（访客来查招募、翻曲目、找音乐学院），曲目条目页与解剖/发声页是 **Read**。**首页不该按 Persuade 打分**——这正是 taste 闸门那 36 条 FAIL 的来源，它把每个面板页当落地页审。

## 二、我们会用到的命令

| 命令 | 用途 | 输出 |
|---|---|---|
| `critique <目标>` | UX 评审，启发式打分 | 分档 + 具体问题 + 改法（不改结构） |
| `audit <目标>` | 技术体检：可访问性、性能、响应式 | 按严重度列缺陷 |
| `polish` | 上线前最后一轮 | 小修清单 |
| `bolder` / `quieter` | 往上推一档 / 往下收 | 方向调整 |
| `typeset` | 字号层级与字体 | 具体数值 |
| `layout` | 间距、节奏、层级 | 栅格与间距值 |
| `clarify` | 界面文案、标签、报错 | 替换句（**本站文案不归我改**，只做提示） |
| `adapt` | 不同尺寸适配 | 断点问题 |
| `optimize` | UI 性能诊断 | 卡顿来源 |
| `harden` | 错误态、i18n、边界 | 缺口清单 |

`init` 会写 PRODUCT.md，`document` 会从现有代码生成 DESIGN.md。这两个可选：不写也能跑，但每次它会先问产品定位，多花一轮。

## 三、评分从哪来

`reference/critique-rubric.md`（约 20KB）是打分表，`reference/audit.md` 是可访问性与性能的判据，`reference/craft-floor.md` 是「不许出现」的地板（紫色渐变、居中堆叠、编造评价、装饰性滚动淡入等）。要复现它的结论，读这三份，不必装启动器。

## 四、用法纪律

- 它先看渲染结果再说话（`scripts/impeccable shot <page>`），不看源码猜。
- 「Refinement 保留，Redesign 替换」：它明确禁止把重设计降级成在旧外观上打磨。我们对应的是——**改版只在必要时做，不做半步**。
- 它要求「brief 优先」：客户钉死的配色、字体、年代不许被它的品味改掉。酒红主题是我们钉的，它不该劝我们换。

## 五、和现有工具的关系

- taste 闸门：继续跑，但当它是**体检报告**，不是判决书。
- `hero-calls.js` 那层动效：用 `audit` 复核 `prefers-reduced-motion` 与布局抖动即可。
- 不引入它的 CSS/组件，纯做评审用。
