# web-quality 方法卡

## 一、可访问性：按 WCAG 的实做顺序查

1. 键盘：能不能 Tab 到、焦点可见、顺序合理、不困在面板里
2. 语义：按钮是 `<button>` 不是 `<div>`，标题层级连贯，图片有替代文本（装饰图用空 alt）
3. 对比度：正文 ≥ 4.5:1，大字 ≥ 3:1；深色模式要单独算一遍
4. 动效：`prefers-reduced-motion` 必须真关掉动画，不是放慢
5. 状态：展开/收起、加载中、空结果、出错，都要有可读的提示

自带的 `scripts/audit-a11y.sh` 能出一遍静态扫描，但它看不出「焦点被遮住」这类问题，渲染后仍要人眼过一遍。

## 二、性能：只看三件事

| 看什么 | 本站现状方向 |
|---|---|
| 首屏关键资源 | 8 个 CSS 串在 `<head>` 里，值得合并且按页拆 |
| 字体 | 中英混排，先确认是否有不可见的字体等待 |
| 图片 | 解剖图与照片是否给了尺寸，避免布局抖动 |

它的口径是「先量再改」：拿真实设备的 CWV，不在本地推测。

## 三、DevTools 驱动检查

替掉「截图 + 肉眼」的做法：直接跑脚本读 `scrollWidth`、`getBoundingClientRect`、`document.styleSheets` 里某条规则是否真的生效。taste 那轮踩过的坑——`@media` 整块失效、来源行被切掉 134px——都是这类可编程检查能当场抓到的。

## 四、纪律

- 三个技能都假设你能起浏览器；起不来就退回到「读 CSS + 算几何」。
- 不要为了指标改结构；先证明指标真的影响到了人。
