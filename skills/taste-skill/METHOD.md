# tasteskill 2.5.1 方法卡（中文摘记）

> 来源：`Leonxlnx/taste-skill` · `skills/taste-skill/SKILL.md`（MIT）
> 本文是我们自己的转述与压缩，不是原文；原文以 `sync.sh` 拉下来的 `upstream/skills/taste-skill/SKILL.md` 为准。

## 一句话

先把「这是一家什么生意」定死，再让版式、配色、元素**抽签**而不是凭感觉挑，文案先写完，最后用脚本在真浏览器里查，查到过闸门为止。

## 九条铁律（它的 house rules，压缩版）

1. 图下不放说明文字；版权署名统一放页脚一行。
2. 每个视觉在 1440 / 1024 / 768 / 390 四个宽度都要真的渲染出来，不能是空底。
3. **一屏一节**：首屏只放 hero；每节高度 1–2 屏（1440×900），下一节的标题不许露头。
4. 左右内容边对齐。
5. 悬停要有反馈：卡片抬 2px、图放大 1.02–1.03、按钮按下下沉、下划线画出来。禁止倾斜、轮播、定时切 tab。
6. 真实照片越多越好；背景、首屏、版式、字体都要更好。
7. 图标用真产品的原色图标，不用手绘替代。
8. 大场面/着色器只在技术类站点（软件、AI、游戏、硬件）出现；咖啡馆、面包店、民宿这类地方一律用照片。
9. 地址只到街区和街道，不写门牌、邮编、坐标；电话不是真号码；邮箱用 `.example`。

## 生意类型决定一切

| 简报 | page type | site-kind |
|---|---|---|
| App / SaaS / AI / 开发者工具 / 金融 | software | software |
| 游戏 | software | gaming |
| 硬件 / 科技设备 | product | tech |
| 其他实体商品 | product | other |
| 雇人的：诊所、律所、工作室 | service | other |
| 人去的：咖啡馆、餐厅、民宿、店 | place | other |

判断口诀：门口真的会发生事（卖咖啡、教学、接待）就是 `place`；只有网店没有门面才是 `product`。

## 抽签，不挑

配色、版式、hero、元素配对都由命令抽出来，并写进 `.taste-skill/*-history.json`，所以下一次不会重复。规则是「取打印出来的第一个」，只有和客户自己的 logo/照片冲突才取第二个。

对我们最有用的一点：**页面的差异不靠灵感，靠机制**。

## 顺序

1. 定类型、定卖什么、定唯一主行动（订房/买票/预约试课/看路线）
2. **先写文案**：h1 说清品类和买家，第一屏给一个硬事实，按钮＝动词＋对象
3. 按「屏」做计划：每节一行，写清它唯一的想法、配什么图、几屏
4. 抽签
5. 搭页面
6. 跑检查 → 修 → 再跑，最多三轮
7. 报告：闸门结论、豁免理由、没查到的东西、假设的事实

## 永不（它列的红线）

- 滚动淡入、整节淡入、文字视差、劫持滚动、随机闪烁
- 库存图冒充客户的产品/人物/场地；产品页从头到尾不给看产品
- 手绘仿一个真 logo；编造评价、客户、数字
- 页面自身设计里出现紫色/淡紫
- 抄参考站的代码、文案、图片或标志性效果
- 为了让检查通过去改工具包自己的文件

## 落在 OperaLab 上怎么用

三处直接对应：

1. **首页首屏**：现在说的是「歌剧机会研究站」，可以更硬——一句品类 + 一句给谁 + 一个硬事实（比如「已核对 N 场 2027 季试唱，每条带官方链接」）。
2. **大师班页**：每场一张卡，卡上放真东西（曲目、截止日、官方链接），不要情绪图。
3. **voice-lab（解剖实验室）**：它是技术类内容，允许一个效果；但一屏一节、左右齐、悬停有反馈这三条现在就能照做。

不适用它的地方：我们是内容/工具混合站，不是公司官网；它的「12–20 张照片铺满」对我们是负担，学它的**结构纪律**，不学它的素材密度。
