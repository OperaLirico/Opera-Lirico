# 每周简报写作规范（按声部版）

这份文件回答一个问题：每期邮件从上到下怎么写，才能让不同声部的读者一眼看到与自己有关的部分，又不显得像营销邮件。

适用范围：Buttondown 上的 `Opera Lirico Weekly`（中文正文，意大利语术语保留原文）。
配套文档：`docs/newsletter-segmentation.md`（技术实现）、`docs/chinese-copywriting-guide.md`（站点通用文案规范）。

## 一、一封邮件的结构

按顺序固定这六段，不要临时加段落：

| 段落 | 写什么 | 长度 |
| --- | --- | --- |
| 1. 开头 | 日期 + 本期收录了几条已核验公告 + 一句“申请前请再读公告” | 2–3 句 |
| 2. 你的声部 | 只在该读者声部命中时出现：一句读公告的提示 + 该声部本周的机会卡（最多 5 条） | 1 句 + 卡片 |
| 3. 一周内截止 | 未来 7 天内截止的公告，不分声部，最多 3 条 | 卡片 |
| 4. 全部开放机会 | 按截止时间列出全部条目，一行一条，带声部与截止 | 列表 |
| 5. 说明 | 简报来源、不构成录取保证 | 1 句 |
| 6. 页脚 | 改声部的方法、退订链接、隐私说明、往期链接 | 固定文案 |

第 2 段由程序按订阅者填写的声部拼接，其余段落所有人看到的一样。所以每期的写作工作量只有第 1 段的开头，和必要时手工补的一条观察。

## 二、标题怎么写

固定格式：

```
Opera Lirico 每周简报｜2026-11-15｜按你的声部
```

- 日期必须真实对应这期的整理日期，不要写成“本周”。
- 不在标题里堆“机会难得”“速看”这类词。收件人关心的是哪一周、有没有与自己相关的东西。
- 标题不做个性化（按声部变标题会让同一封邮件出现多个标题，也容易触发垃圾邮件规则）。

## 三、每条机会卡的写法

四行，顺序固定：

1. **标题**：直接用公告标题原文，链接到官方公告。不要翻译剧目名里的专有名词。
2. **主办方 / 地点**：写机构名和城市；不确定就写“地点以官方公告为准”。
3. **声部 / 截止**：声部用中文标签，截止写到分钟并标“意大利时间”。
4. **资格摘要**：一条公告里最容易踩坑的那一条（出生年份、居留要求、语言要求、曲目背谱），一句到两句，直接来自公告。

不要写“值得一试”“机会很大”“别错过”。判断留给读者。

## 四、声部提示句怎么写

每个声部一段固定提示，讲“读这一声部的公告时要先确认什么”。这不是鼓励，是省时间的经验：

- **女高音**：公告常在抒情与花腔之间分流，先看是否指定角色或音域，再决定准备曲目。
- **女中音**：岗位少但角色生命周期长；只写剧目没写角色的公告，先去附件里找具体角色。
- **女低音**：部分意大利公告把 contralto 与 mezzo 写在同一行，先确认要哪一种。
- **假声男高音**：多来自巴洛克剧目与古乐团；countertenor / alto / contratenor 常指同一类。
- **男高音**：试唱多要求意大利语咏叹调；公告写了角色名，先对照角色音域与自己的舒适区。
- **男中音**：常一次列多个角色；先看哪几个角色由同一次试唱覆盖。
- **男低音**：区分 basso profondo 与 basso cantante，两者音域与角色要求不同。
- **不限声部**：不指定声部时，把全部机会按截止时间列出来。

这些句子写成“先看什么”，不写成“你一定能行”。以后要改，也保持这个句式。

## 五、开头段怎么写

模板：

```
整理日期：2026-11-15。本期收录 7 条已核验且仍在报名的官方公告。
申请前请再读一遍主办方原文，日期与资格以公告为准。
```

如果这期有值得说明的变化（例如某个大项目提前截止、某类声部这周没有新机会），在这一段后补一到两句，且必须写清依据：

```
AsLiCo 的预选场次这周新增了两场，日期在公告页第二条，报名时要选场次。
```

不写“本周更新了不少内容”这种没有信息量的句子。

## 六、不要写的东西

| 不要 | 原因 |
| --- | --- |
| “机会难得”“抓紧时间”“手慢无” | 招聘公告不是促销，这类词会让专业读者直接关掉 |
| “相信你一定可以”“祝你好运” | 群发邮件里的祝福是空的，每期都出现会让人麻木 |
| “你可能不知道……” | 假设读者无知，语气居高临下 |
| 未核实的日期或资格 | 简报只写已核验的官方信息，宁可少写一条 |
| 订阅者个人信息 | 声部只用于分拣内容，正文里不要出现“给男高音的你”以外的个人化信息 |
| 大段翻译 | 公告标题保留原文，摘要只写关键条件，不做逐段翻译 |

## 七、发送前的检查清单

1. Buttondown 里这封草稿的标题、日期是否对得上。
2. 用“订阅者预览”任选一个填写了声部的订阅者，确认“你的声部”段落出现且内容属于该声部。
3. 再用一个声部不同的订阅者预览一次，确认出现的是另一段。
4. 确认“一周内截止”里的日期都在未来，没有已经过期的公告。
5. 确认页脚的退订链接与隐私说明链接可点。
6. 确认没有出现 token、后台地址、内部审核状态之类的内部信息。

程序只负责生成草稿，发送这一步始终由人点。这是这条链路上唯一不能自动化的一步。

## 八、每期的时间安排

- 周一 09:00（意大利时间）：`Weekly email digest (draft only)` 生成草稿与预览（GitHub Actions，cron 08:00 UTC）。
- 周一白天：人按上面清单检查，必要时改开头段。
- 发送：在 Buttondown 里点发送，或在后台把 `status` 改成 `about_to_send`（不建议，容易误发）。
