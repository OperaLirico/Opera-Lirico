# 解剖板块评估：现在做到哪一步，下一步该做什么

评估时间：2026-11-16。对象是 `voice-anatomy.html`（发声机制实验室）与 `larynx-mechanism.html`（喉部发声机制实验室）。以下数据来自当天对线上页面与仓库的实际读取，不是印象。

## 一句话结论

这个板块的可信度已经超过大多数声乐科普站：结构、来源、免责都很干净，三维模型用的是大学医学解剖项目的真模型。但它现在停在“可旋转的模型 + 可拖动的示意图形”这一层，离“解剖实验室”还差三步：肌肉不可点、声音不可听、学完不知道下一步做什么。所以：**没有发挥到极致。**

## 四个维度打分

- **结构可信度**：高。模型有出处，页面自己写明“示意比例、非手术解剖图”，不把示意图冒充为真实形变。
- **交互深度**：偏低。滑块改变的是同一张示意图的形态，模型本身不会因为选某个机制而高亮对应肌肉；用户只能“看文案 + 自己转到那个角度”。
- **教学闭环**：缺。两页都没有“学完自测”和“下一步练什么”，用户读完就结束。
- **运行成本**：偏高。三维模型全部来自 sketchfab.com 的 iframe，国内网络与移动端都会吃亏，断网或第三方故障时页面只剩文字；三张线描图约 1.4 MB（已做 lazy）。

## 优先级建议

### P1 肌肉可点，模型能对上号（收益最高）

把喉内肌线描图变成带热区的图：在 `assets/anatomy/larynx-intrinsic-muscles.png` 上叠一层透明 SVG，五块肌肉各一个多边形，点哪块就把右侧 readout 换到对应机制、并把“在模型里转到哪里找它”写成一句操作指引。这张图的热区坐标不是猜的：图是我按解剖体位画的，必须先人工标一遍边界，标完在页面上点一轮验证再上线。工作量中等，但这是“抽象”变成“可操作”的关键一步。

### P2 三段声音样本（让声门状态和听感对上）

现在的页面只说“靠拢 50%”，用户没有听觉参照。建议在声门图旁放三段短音频：正常发声、高音/假声、气息声，各 5–8 秒，标清“声门接触面积与气流比例不同”。**注意版权**：只能用自己录的、或明确授权可再分发的样本；不能用大师班录音直接剪。

### P3 三维模型加降级层

给每个 iframe 位置放一张静态封面图（或直接复用线描图），模型没加载出来时显示“模型暂不可用，先用线描图看结构”，而不是一片空白。同时把 iframe 的 `loading="lazy"` 与首屏可见模型分开处理，避免一进页面就拉三个模型。

### P4 每页三道自测题（纯前端，无后端）

例如“声门后部闭合主要靠哪组肌肉”“假声带在真声带的上方还是下方”“杓状软骨的肌突被哪块肌肉拉动”。答完给一句解释，不记分、不收集数据。成本很低，但它把“看过”变成“记住”。

### P5 结构化数据与分享图

给两页加 `LearningResource` JSON-LD，并各自配一张 `og:image`（可以直接用线描图裁一张横版）。现在两页分享到微信/小红书时没有专属缩略图。

### P6 术语中英对照表

页面里中英混排（Arytenoid、LCA、PCA），但没有一处集中对照表。做一张可折叠的术语表，对非中文母语的用户也有用。

### P7 和大师班内容互链

解剖页现在是孤岛：大师班页、曲目页都不指向它。至少在大师班条目里加一句“这个技术点对应解剖页的哪一节”，让学习路径能串起来。

## 两个已知约束（没解决，记录在此）

1. **部署触发路径不含 `assets/**`**。`pages-deploy.yml` 的 `paths` 列表里没有资源目录，所以只换图不碰页面时，提交不会重建站点。尝试用机器人工作流去补这两行失败了：`GITHUB_TOKEN` 没有修改 workflow 文件的权限，要改只能由带 `workflow` 权限的人手动提交。目前的做法是“换图必跟页面一起提”，能绕过去。
2. **线描图的解剖准确性不做逐结构担保**。三张图是按文献重绘的教学图版，结构关系与方位是对的，细节（软骨轮廓、肌纤维走向）不是标本级精度。页面已写明“不作为临床或诊断依据”，模型仍是第一参照。
